# ระบบต้นทุนและสต๊อกกาแฟ "เม่อะ เต เต"

บันทึกตามลำดับ 6 ขั้นตรงตามที่คุณวางไว้ ต้นทุนไหลต่อกันทุกขั้น เงินที่จ่ายค่ากะลาวันนี้จะไปโผล่ในกำไรของซอง 250g ที่ขายเดือนหน้า

```
1 ซื้อกะลา ──► 2 ผลิตสารเขียว ──► 3 ผลิตเมล็ดคั่ว ──► 5 ขาย
   ราคา/kg       ค่าสี + ค่าส่ง      ค่าแรง + ค่าเช่าเครื่อง    ซอง สติ๊กเกอร์
   ค่าขนส่ง      น้ำหนักหาย          น้ำหนักหาย                กล่อง เทป ค่าส่ง
                      │                 แยก 4 ระดับ
                 ขายเป็น kg ได้          │
                                    4 ซื้อวัสดุอุปกรณ์
                                          │
                            6 สรุป: ต่อซอง · ต่อวัน · ต่อเดือน · ต่อปี
```

## ติดตั้ง

**ขั้นที่ 1 — Google Sheets (ครั้งเดียว ~7 นาที)**

1. สร้าง Google Spreadsheet ใหม่
2. **ส่วนขยาย → Apps Script** ลบโค้ดเดิม วางเนื้อหาจาก `Code.gs` แล้วบันทึก
3. เลือกฟังก์ชัน **`setupSheets`** กด **เรียกใช้** แล้วอนุญาตสิทธิ์
4. เลือกฟังก์ชัน **`seedCoffeeCatalog`** กด **เรียกใช้** อีกครั้ง — ระบบสร้างรายการสินค้าและสูตรซองตั้งต้นให้ทั้งชุด
5. **ทำให้ใช้งานได้ → การทำให้ใช้งานได้ใหม่** → **เว็บแอป** → ดำเนินการในฐานะ **ฉัน** → เข้าถึงได้ **ทุกคน**
6. คัดลอก **URL** ที่ลงท้ายด้วย `/exec`

**ขั้นที่ 2 — เอาแอปขึ้นเว็บ (ผ่าน GitHub)**

เก็บโค้ดไว้ที่ GitHub แล้วให้ Cloudflare Pages ดึงไปเผยแพร่ให้อัตโนมัติ ข้อดีคือมีประวัติการแก้ไขทุกครั้ง ย้อนกลับได้เมื่อแก้แล้วพัง

1. สมัคร https://github.com → กด **+** มุมขวาบน → **New repository** → ตั้งชื่อ เช่น `mtt-coffee` → เลือก **Private** → **Create repository**
2. กดลิงก์ **uploading an existing file** แล้วลากไฟล์ทั้งหมดในโปรเจกต์เข้าไปวาง → **Commit changes**
3. เข้า https://dash.cloudflare.com → **Compute (Workers & Pages)** → **Create** → แท็บ **Pages** → **Connect to Git**
4. เลือก repo ที่เพิ่งสร้าง แล้วตั้งค่า build ดังนี้ — Framework preset: **None** · Build command: **เว้นว่าง** · Build output directory: **`/`**
5. กด **Save and Deploy** ได้ลิงก์ `https://ชื่อโปรเจกต์.pages.dev`

**เวลาแก้ไขแอปภายหลัง** เข้า repo บน GitHub → กดที่ไฟล์ → กดรูปดินสอ ✏️ → แก้ → **Commit changes** เว็บจะอัปเดตเองใน 1-2 นาที ไม่ต้องอัปโหลดใหม่ทั้งชุด

> ไฟล์ `_headers` เป็นตัวกำหนดว่าไฟล์ไหนแคชได้นานแค่ไหน อย่าลบออก ไม่งั้นเวลาอัปเดตแอปแล้วเครื่องที่ติดตั้งไว้อาจยังเห็นเวอร์ชันเก่าค้าง

**ขั้นที่ 3 — ติดตั้งลงมือถือ**
Android (Chrome): เมนู ⋮ → ติดตั้งแอป · iPhone (Safari): ปุ่มแชร์ → เพิ่มไปยังหน้าจอโฮม
เปิดครั้งแรกให้วาง URL จากขั้นที่ 1

## เรื่องที่ต้องรู้ก่อนใช้

### ชื่อสินค้าเมล็ดคั่ว

| ชื่อสินค้า | ระดับคั่ว | รหัส |
|---|---|---|
| Little My | คั่วอ่อน | RB-LT |
| Wednesday | คั่วกลาง | RB-MD |
| ตาหนวด | คั่วกลางค่อนเข้ม | RB-MDK |
| เห็น"นม"สู้ตาย | คั่วเข้ม | RB-DK |

ระบบใช้ **ระดับคั่ว** เป็นตัวเชื่อมภายใน ส่วนชื่อแบรนด์เป็นป้ายที่แสดงบนหน้าจอ ทั้งหน้าคั่วและหน้าขายจึงโชว์ชื่อแบรนด์คู่กับระดับคั่วเสมอ เช่น *Wednesday · คั่วกลาง* เลือกอันไหนก็ตัดสต๊อกของอันนั้นตรงกัน

อยากเปลี่ยนชื่อภายหลังก็แก้ที่ชีต **สินค้า** คอลัมน์ *ชื่อสินค้า* ได้เลย ขอแค่อย่าแก้คอลัมน์ *ระดับคั่ว* เพราะเป็นตัวที่ระบบใช้จับคู่

**ถ้าเคยติดตั้งเวอร์ชันก่อน** วางโค้ดใหม่ทับ แล้วรันฟังก์ชัน **`renameBeansToBrand`** หนึ่งครั้ง ระบบจะเปลี่ยนชื่อให้ทั้ง 4 รายการโดยจับคู่จากระดับคั่ว — สต๊อก ล็อต ต้นทุน และประวัติการขายที่บันทึกไว้แล้วไม่ถูกกระทบ

### ขั้นที่ 3 — การคั่วและการปันส่วนต้นทุน

กรอก **สารเขียวที่ตัดเบิก** เป็นยอดเดียว แล้วกรอก **เมล็ดคั่วที่ได้** แยกตามระดับ

หน้าจอแสดงช่องกรอกครบทั้ง 4 ระดับเสมอ — คั่วอ่อน · คั่วกลาง · คั่วกลางค่อนเข้ม · คั่วเข้ม — ระดับไหนไม่ได้คั่วรอบนั้นก็ปล่อยว่างไว้ แต่ละช่องบอก Yield มาตรฐานและยอดคงเหลือปัจจุบันของระดับนั้นกำกับไว้ให้

ถ้าระดับไหนยังไม่เคยมีรายการสินค้าในระบบ ช่องนั้นจะขึ้นว่า *จะสร้างรายการให้อัตโนมัติ* — พอกดบันทึกครั้งแรกระบบจะสร้างรายการเมล็ดคั่วของระดับนั้นให้เอง ไม่ต้องไปเพิ่มสินค้าเองก่อน

รายชื่อระดับดึงมาจากชีต **ตั้งค่า** แถว *ระดับการคั่ว* ถ้าอยากเพิ่มหรือเปลี่ยนชื่อระดับ แก้ที่นั่นแล้วช่องกรอกจะเปลี่ยนตาม

ค่าแรงจ้างคั่วกับค่าเช่าเครื่องคั่วใส่เป็นยอดรวมของทั้งรอบ

**ระบบปันส่วนสารเขียวให้แต่ละระดับอย่างไร** — คั่วเข้มน้ำหนักหายมากกว่าคั่วอ่อน แปลว่าเมล็ดคั่วเข้ม 1 kg กินสารเขียวมากกว่าเมล็ดคั่วอ่อน 1 kg ระบบจึงใช้ **Yield มาตรฐานรายระดับ** ในชีตตั้งค่าเป็นตัวถ่วงน้ำหนัก

```
ค่าถ่วงน้ำหนักของระดับ = เมล็ดคั่วที่ได้ ÷ Yield มาตรฐานของระดับนั้น
สารเขียวที่ปันส่วน     = สารเขียวทั้งรอบ × (ค่าถ่วงน้ำหนักของระดับ ÷ ผลรวมค่าถ่วงน้ำหนัก)
```

ค่าแรงและค่าเช่าเครื่องปันส่วนด้วยสัดส่วนเดียวกัน ผลคือคั่วเข้มมีต้นทุนต่อ kg สูงกว่าคั่วอ่อนตามความเป็นจริง แทนที่จะเฉลี่ยเท่ากันหมด

ค่าเริ่มต้นที่ตั้งไว้คือ คั่วอ่อน 87% · คั่วกลาง 84% · คั่วกลางค่อนเข้ม 82% · คั่วเข้ม 79% แก้ได้ที่ชีต **ตั้งค่า** แถว *Yield มาตรฐานรายระดับ (%)* ยิ่งใส่ใกล้ของจริง การปันส่วนยิ่งแม่น

**ตัวอย่าง** สารเขียว 100 kg ได้คั่วอ่อน 30 kg คั่วกลาง 25 kg คั่วเข้ม 20 kg (รวม 75 kg หายไป 25 kg)

| ระดับ | สารเขียวที่ปันส่วน | ได้ | Yield จริง |
|---|---|---|---|
| คั่วอ่อน | 38.50 kg | 30 kg | 77.9% |
| คั่วกลาง | 33.23 kg | 25 kg | 75.2% |
| คั่วเข้ม | 28.27 kg | 20 kg | 70.8% |

Yield จริงที่แสดงจะต่ำกว่ามาตรฐานทุกระดับ เพราะรอบนี้ผลผลิตรวมได้แค่ 75% หน้าจอจะเตือนเมื่อต่างจากมาตรฐานเกินที่ตั้งไว้ — ถ้าเห็นเตือนบ่อย แปลว่าควรปรับตัวเลขมาตรฐานให้ตรงความจริง หรือไปคุยกับคนคั่ว

### ขั้นที่ 5 — การขายตัดสต๊อกอย่างไร

ขาย "คั่วกลาง 250g จำนวน 4 ซอง" ระบบจะตัด
- เมล็ดคั่วกลาง 1.0 kg
- ซอง 250g จำนวน 4 ใบ
- สติ๊กเกอร์ 4 ดวง

แล้วบวกกล่องกับเทปตามที่กรอก ระดับออร์เดอร์ ไม่ปันเข้าต้นทุนซอง เพราะออร์เดอร์ 1 ซองกับ 10 ซองใช้กล่องเท่ากัน ถ้าปันเข้าต้นทุนซองจะทำให้ตั้งราคาขายส่งผิด

ถ้าอยากเปลี่ยนว่าขนาดไหนใช้ซองอะไร แก้ที่ ขั้นที่ 4 → ปุ่มสูตรซอง

### ขั้นที่ 6 — ตารางต้นทุนต่อซอง

แยกให้เห็น 5 บรรทัด: กาแฟกะลา / ค่าสี+ค่าส่ง / ค่าแรง+ค่าเช่าคั่ว / ซอง / สติ๊กเกอร์ แล้วรวมเป็นต้นทุนต่อซอง พร้อมราคาแนะนำตามเป้าหมายกำไร และบอกด้วยว่าซองนั้นใช้กะลากี่ kg

ตัวเลขคำนวณจากต้นทุนเฉลี่ยปัจจุบันกับ yield จริงที่บันทึกไว้ ยิ่งบันทึกครบ ตัวเลขยิ่งตรง

### ค่าที่ควรตั้งในชีต ตั้งค่า

- **Yield มาตรฐาน สี / คั่ว** — ใส่ตัวเลขที่ใกล้ของจริง ระบบจะเตือนเมื่อรอบไหนผิดปกติ
- **อายุสารเขียว / เมล็ดคั่ว (วัน)** — ใช้ตั้งวันหมดอายุอัตโนมัติ
- **เป้าหมายอัตรากำไร (%)** — ใช้คำนวณราคาแนะนำ
- **ค่าใช้จ่ายคงที่ต่อเดือน** — ค่าเช่าที่เก็บ ค่าน้ำค่าไฟ ค่าแรงประจำ ใส่แล้วสรุปจะโชว์กำไรสุทธิหลังหักด้วย
- **อีเมลรับแจ้งเตือน** — ใส่แล้วไปตั้ง **ทริกเกอร์ → เพิ่มทริกเกอร์** เลือก `dailyAlert` รายวัน

## แก้ไขและลบรายการ

ทุกฟอร์มบันทึกมีลิงก์ **รายการที่บันทึก** ที่มุมขวาบน หรือเข้าจากหน้าบันทึก → *ดู แก้ไข หรือลบรายการที่บันทึกไว้*

หน้านี้แสดง 40 รายการล่าสุดของแต่ละประเภท แต่ละแถวมีปุ่ม **✎ แก้ไข** และ **🗑 ลบ**

**ลบ** — ระบบย้อนผลกระทบต่อสต๊อกให้อัตโนมัติ แล้วทำเครื่องหมาย *ยกเลิก* ที่แถวนั้นในชีต

- ลบรายการซื้อ → ถอนของออกจากคลังและคืนต้นทุนเฉลี่ยกลับเป็นค่าเดิมพอดี
- ลบงานสี → คืนกะลาที่ตัดเบิก และถอนสารเขียวที่ได้ออก
- ลบงานคั่ว → คืนสารเขียว และถอนเมล็ดคั่วทุกระดับในเอกสารนั้นออก
- ลบการขาย → คืนเมล็ดคั่วเข้าล็อตเดิม พร้อมคืนซอง สติ๊กเกอร์ กล่อง และเทป

แถวยังอยู่ในชีตแต่ไม่ถูกนับในยอดสรุป กราฟ หรือ yield อีกต่อไป ที่ทำแบบนี้เพราะถ้าลบแถวทิ้งจริง จะตรวจย้อนหลังไม่ได้ว่าตัวเลขเคยเป็นอย่างไร ถ้าอยากให้หายจากชีตจริง ๆ ลบแถวเองได้หลังจากกดลบในแอปแล้ว

**แก้ไข** — กด ✎ ระบบดึงตัวเลขเดิมมาใส่ในฟอร์มให้ พร้อมแถบสีม่วงบอกว่ากำลังแก้เอกสารไหน แก้ตัวเลขแล้วกดบันทึกตามปกติ ระบบจะยกเลิกของเดิมและบันทึกใหม่ให้ในครั้งเดียว เอกสารใหม่จะมีหมายเหตุว่าแก้มาจากเลขที่เดิม

### ช่องทางการขาย

มี 3 แบบ — **นัดรับ · ส่งพัสดุ · ฝากส่ง** เลือกได้ในหน้าขาย และรายงานสรุปจะแยกกำไรตามช่องทางให้ดูว่าแบบไหนเหลือกำไรจริงมากกว่ากัน

เมื่อเลือก **นัดรับ** ระบบตั้งค่าให้อัตโนมัติเป็น *ไม่ใช้กล่อง* และค่าส่งเป็น 0 ทั้งสองฝั่ง เพราะรับของกันเองไม่มีต้นทุนส่วนนี้ ถ้ารอบไหนนัดรับแต่ยังใส่กล่องให้ลูกค้า ก็เลือกกล่องกลับเข้าไปได้ตามปกติ

**ถ้าเคยติดตั้งเวอร์ชันก่อน** รันฟังก์ชัน **`updateChannels`** หนึ่งครั้ง ระบบจะเปลี่ยนรายการช่องทางในชีตตั้งค่าให้ ออร์เดอร์เก่าที่บันทึกช่องทางเดิมไว้แล้วไม่ถูกแก้ ยังดูย้อนหลังได้ปกติ

### บับเบิ้ลกันกระแทก

ในหน้าขายมีช่อง **บับเบิ้ลกันกระแทก (เมตร)** อยู่คู่กับเทปกาว ใส่จำนวนเมตรที่ใช้จริงในออร์เดอร์นั้น ระบบจะตัดสต๊อกและคิดเข้าต้นทุนให้ บรรทัดสรุปจะแสดงเป็น *กล่อง + บับเบิ้ล + เทป*

หน่วยตั้งต้นเป็น **เมตร** ถ้าร้านซื้อมาเป็นม้วนแล้วนับเป็นม้วนสะดวกกว่า ให้แก้หน่วยที่ชีต **สินค้า** แถว *บับเบิ้ลกันกระแทก* คอลัมน์ *หน่วยนับ* เป็น `ม้วน` แล้วเวลาซื้อกับเวลาขายก็กรอกเป็นม้วนให้ตรงกัน

เหมือนวัสดุอื่น ๆ ต้องบันทึกซื้อในขั้นที่ 4 ก่อน ไม่งั้นต้นทุนจะเป็น 0 และระบบจะขึ้นเตือนให้เห็นตอนขาย

**ถ้าเคยติดตั้งเวอร์ชันก่อน** วางโค้ดใหม่ทับ แล้วรันฟังก์ชัน **`seedBubbleWrap`** หนึ่งครั้ง ระบบจะเพิ่มรายการให้โดยไม่แตะข้อมูลเดิม

### เลือกขนาดกล่องพัสดุตอนขาย

ในขั้นที่ 5 ช่อง **ขนาดกล่องพัสดุ** เป็นดรอปดาวน์ให้เลือกตามเบอร์กล่อง แต่ละตัวเลือกบอกขนาด ต้นทุนต่อใบ และยอดคงเหลือไว้ในบรรทัดเดียว เช่น

```
เบอร์ A (14×20×6 ซม.) · 7 บ. · เหลือ 25
```

ตัวเลือกแรกในดรอปดาวน์คือ **— ไม่ใช้กล่อง —** สำหรับการขายที่ไม่ต้องแพ็คกล่อง เช่น นัดรับหน้าร้าน เลือกอันนี้แล้วช่องจำนวนกล่องจะถูกปิดไว้ และไม่มีต้นทุนกล่องเข้าไปในบิล

เลือกเบอร์ไหน ระบบก็ตัดสต๊อกและคิดต้นทุนของเบอร์นั้น หน้าสรุปจะโชว์ชื่อกล่องที่ใช้ จำนวน และราคาต่อใบให้ตรวจก่อนบันทึก

ขนาดที่ให้มาเป็นเบอร์มาตรฐานที่ใช้กันทั่วไป — 00 · 0 · A · AA · B · C · D — ตัวเลขขนาดในวงเล็บเป็นค่าที่พบบ่อย ถ้าของที่ร้านใช้ไม่ตรง แก้ชื่อในชีต **สินค้า** คอลัมน์ *ชื่อสินค้า* ได้เลย หรือจะเพิ่มเบอร์อื่นก็กดปุ่ม **+ เพิ่มขนาดกล่อง** ในหน้าขาย ขอแค่ตั้งชื่อให้มีคำว่า "กล่อง" อยู่ในชื่อ ระบบจะดึงเข้าดรอปดาวน์ให้เอง

**ถ้าเคยติดตั้งเวอร์ชันก่อน** วางโค้ดใหม่ทับ แล้วรันฟังก์ชัน **`seedBoxSizes`** หนึ่งครั้ง ระบบจะเพิ่มเบอร์กล่องมาตรฐานเข้าไปโดยไม่แตะรายการกล่องเดิมที่มีอยู่ และไม่กระทบสต๊อกหรือประวัติใด ๆ

อย่าลืมบันทึกซื้อกล่องแต่ละเบอร์ในขั้นที่ 4 ด้วย เบอร์ที่ยังไม่เคยซื้อจะขึ้นว่า *ยังไม่มีต้นทุน* และคิดเป็น 0 บาท

### กล่องและเทปขึ้นเป็น 0 ในการขาย

ถ้าตอนขายเห็นบรรทัด *กล่อง + เทปกาว* เป็น 0 แปลว่ากล่องหรือเทปยังไม่มีต้นทุนในระบบ ต้นทุนของวัสดุทุกชนิดจะถูกตั้งก็ต่อเมื่อบันทึกซื้อใน **ขั้นที่ 4 (ซื้อวัสดุอุปกรณ์)** ก่อน

วิธีแก้ — เข้าขั้นที่ 4 บันทึกซื้อกล่องพัสดุและเทปกาว ใส่จำนวนกับราคาที่ซื้อมา ระบบจะคำนวณต้นทุนต่อใบ/ต่อม้วนให้ หลังจากนั้นการขายทุกครั้งจะดึงต้นทุนกล่องและเทปเข้าไปคิดกำไรอัตโนมัติ

ตอนนี้หน้าขายจะเตือนให้เห็นชัดเมื่อกล่องหรือเทปยังไม่มีต้นทุน และถามยืนยันก่อนบันทึกถ้ายังคิดเป็น 0 อยู่ ระบบยังตัดจำนวนกล่องออกจากสต๊อกให้ถูกต้องเสมอ เพียงแต่มูลค่าจะเป็น 0 จนกว่าจะบันทึกราคาซื้อ

### ลบรายการขายทั้งหมดแล้วเริ่มบันทึกใหม่

ถ้าต้องการล้างรายการขายทั้งหมดเพื่อบันทึกใหม่ ให้รันฟังก์ชัน **`deleteAllSales`** ใน Apps Script ครั้งเดียว

ระบบจะคืนสต๊อกให้ครบทุกอย่างที่การขายเคยตัดไป — เมล็ดคั่ว ซอง สติ๊กเกอร์ กล่อง และเทป — แล้วทำเครื่องหมายยกเลิกบิลขายทั้งหมด **ข้อมูลส่วนอื่นไม่ถูกแตะเลย** ทั้งการซื้อกะลา ผลิตสารเขียว ผลิตเมล็ดคั่ว และซื้อวัสดุ

ต้องคืนวัสดุด้วยไม่ใช่แค่เมล็ดคั่ว เพราะถ้าคืนแค่เมล็ด พอบันทึกขายใหม่ ซองกับสติ๊กเกอร์จะถูกตัดซ้ำเป็นรอบที่สอง ยอดคงเหลือจะขาดไปเรื่อย ๆ

เมื่อรันเสร็จจะได้ข้อความสรุปว่าคืนอะไรไปเท่าไหร่บ้าง ให้เทียบกับของจริงก่อนเริ่มบันทึกใหม่

ถ้าอยากให้ชีตสะอาดไม่มีแถวที่ยกเลิกค้างอยู่ รันฟังก์ชัน **`purgeCancelledSales`** ต่ออีกครั้ง แต่ควรตรวจสต๊อกให้แน่ใจก่อน เพราะลบแถวออกแล้วย้อนกลับไม่ได้

### ข้อจำกัดที่ต้องรู้

**ถ้าของถูกใช้ต่อไปแล้ว จะลบไม่ได้** เช่น ซื้อกะลามา 100 kg แล้วเอาไปสีแล้ว 60 kg ระบบจะไม่ยอมให้ลบรายการซื้อนั้น และแจ้งว่า *ล็อตนี้ถูกใช้ไปแล้ว 60 kg — ต้องยกเลิกรายการที่ใช้ของล็อตนี้ก่อน*

วิธีแก้คือไล่ลบจากปลายทางย้อนกลับมา: ลบการขายก่อน แล้วค่อยลบงานคั่ว งานสี แล้วจึงลบรายการซื้อ นี่เป็นข้อจำกัดจริงของการคิดต้นทุน ไม่ใช่ข้อจำกัดของโปรแกรม — เพราะถ้าปล่อยให้ลบได้ ต้นทุนของสินค้าที่ผลิตต่อไปแล้วจะกลายเป็นตัวเลขที่ไม่มีที่มา

**การตรวจนับยกเลิกไม่ได้** ถ้ากรอกยอดนับผิด ให้ตรวจนับใหม่ด้วยตัวเลขที่ถูกต้อง ระบบจะปรับให้ตรงเอง

**การแก้ไขต้องออนไลน์** ต่างจากการบันทึกใหม่ที่ทำออฟไลน์ได้ เพราะระบบต้องอ่านข้อมูลเดิมจากชีตก่อน

### ถ้าเคยติดตั้งเวอร์ชันก่อนหน้า

วางโค้ดใหม่ทับแล้วรัน **`setupSheets`** อีกครั้ง ระบบจะเติมคอลัมน์ *สถานะ* ให้ชีตเดิมโดยไม่แตะข้อมูลที่มีอยู่ รายการเก่าทั้งหมดจะถือเป็นรายการที่ใช้งานอยู่ตามปกติ

## ใบเสร็จรับเงิน

### ข้อมูลร้านบนใบเสร็จ

ชื่อร้าน ที่อยู่ เลขผู้เสียภาษี โทร ธนาคาร ชื่อบัญชี เลขที่บัญชี โลโก้ **มีค่าตั้งต้นอยู่ในโค้ดแล้ว** ใบเสร็จจึงพิมพ์ออกมาครบถึงแม้ชีตตั้งค่าจะยังว่าง

ถ้ากรอกค่าในชีตตั้งค่า **ค่าในชีตจะถูกใช้ก่อนเสมอ** กรอกเฉพาะช่องที่อยากเปลี่ยนก็ได้ ช่องที่เว้นว่างจะใช้ค่าตั้งต้น

> **ถ้าไม่อยากให้เลขบัญชีอยู่ในโค้ด** (เพราะโค้ดอัปขึ้น GitHub) ให้กรอกเลขบัญชีในชีตตั้งค่า แล้วลบค่า `acctNo` ในตัวแปร `SHOP_DEFAULT` ที่หัวไฟล์ `Code.gs` ออก เปลี่ยนเป็น `''` ระบบจะอ่านจากชีตแทน

**ทางลัด** รันฟังก์ชัน **`setShopInfo`** ระบบจะเขียนข้อมูลร้านทั้งชุดลงชีตตั้งค่าให้เลย ไม่ต้องพิมพ์เอง

**ตรวจว่าจะพิมพ์อะไรออกมา** รันฟังก์ชัน `checkSettings` แล้วดูหัวข้อ *— ข้อมูลที่จะพิมพ์บนใบเสร็จจริง —* ในบันทึกการดำเนินการ

> **ข้อมูลพวกนี้อยู่ในชีตของคุณเท่านั้น ไม่ได้อยู่ในโค้ดที่อัปขึ้น GitHub** โดยเฉพาะเลขบัญชีธนาคาร ถ้าเปลี่ยนบัญชีหรือย้ายที่อยู่ก็แก้ในชีตได้เลย ไม่ต้องแตะโค้ด

### วิธีออกใบเสร็จ

ทำได้ 2 ทาง

- **ทันทีหลังบันทึกขาย** — จะมีปุ่ม *ออกใบเสร็จของบิลที่เพิ่งบันทึก* โผล่ขึ้นมา
- **ย้อนหลัง** — เข้า บันทึก → ดูรายการที่บันทึกไว้ → เลือกประเภท *5 ขาย* → กดปุ่ม 🧾 ที่บิลนั้น

จากนั้นกรอกข้อมูลลูกค้า แล้วกด **สร้างใบเสร็จ** หน้าใบเสร็จจะเปิดขึ้นมาใหม่ กดปุ่ม **พิมพ์ / บันทึกเป็น PDF**

- อยากได้ไฟล์ → เลือกปลายทางเป็น *บันทึกเป็น PDF*
- อยากปริ้น → เลือกเครื่องพิมพ์ได้เลย

### ต้องแนบหลักฐานการรับเงินก่อนออกใบเสร็จ

ลำดับการทำงานคือ **ขาย → แนบหลักฐาน → ออกใบเสร็จ** ปุ่มออกใบเสร็จจะยังไม่ขึ้นจนกว่าจะแนบหลักฐานของบิลนั้น

**วิธีแนบ** เข้า บันทึก → ดูรายการที่บันทึกไว้ → *5 ขาย* กดปุ่ม **📎** ที่บิลนั้น แล้วเลือกภาพสลิปจากเครื่องหรือถ่ายใหม่ รองรับไฟล์ภาพและ PDF ขนาดไม่เกิน 8MB

บิลที่ยังไม่แนบจะขึ้นข้อความ *ยังไม่แนบหลักฐาน* สีเหลืองใต้รายการ

ไฟล์เก็บในโฟลเดอร์ Drive ที่ตั้งไว้ในชีตตั้งค่า หัวข้อ *โฟลเดอร์ Drive เก็บหลักฐานการรับเงิน* ตั้งชื่อไฟล์เป็น เลขที่บิล + ชื่อลูกค้า + วันที่ ให้อัตโนมัติ

- **📎** ยังไม่แนบ · กดเพื่อเลือกไฟล์
- **🖼** แนบแล้ว · กดเพื่อเปิดดู หรือเลือกไฟล์ใหม่แทนที่ของเดิม (ไฟล์เก่าจะถูกย้ายลงถังขยะ)

ถ้าอยากปิดการบังคับ ให้แก้ชีตตั้งค่า หัวข้อ *บังคับแนบหลักฐานก่อนออกใบเสร็จ* เป็น `ไม่`

> ไฟล์หลักฐานจะถูกตั้งสิทธิ์เป็น "ใครมีลิงก์ก็เปิดได้" เพื่อให้ลูกค้าสแกน QR แล้วเปิดดูได้ ถ้าไม่ต้องการให้ลูกค้าเห็น ให้ติ๊ก QR ออกตอนออกใบเสร็จ

### QR บนใบเสร็จ

QR ที่พิมพ์บนใบเสร็จคือ **ลิงก์ไปยังภาพหลักฐานการรับเงิน** ของบิลนั้น ลูกค้าสแกนแล้วเปิดดูสลิปได้ทันที ใช้ยืนยันว่าชำระเงินแล้วจริง

ติ๊กออกได้ตอนออกใบเสร็จถ้าไม่อยากให้แสดง

### รูปแบบและขนาดตัวอักษร

ใบเสร็จใช้ฟอนต์ **Tahoma** ทั้งหน้า ปรับขนาดให้ลงพอดี A4 หน้าเดียว ตารางรายการสินค้ากับตารางยอดเงินเป็นตารางเดียวกัน เส้นจึงต่อเนื่องกันสนิท และยอดเงินตรงคอลัมน์กับ *ราคา/หน่วย* และ *จำนวนเงิน* พอดี

> Tahoma มีติดมากับ Windows และ Android อยู่แล้ว ถ้าเครื่องไหนไม่มีจะใช้ฟอนต์ใกล้เคียงแทนโดยอัตโนมัติ

### เก็บใบเสร็จอัตโนมัติใน Google Drive

ทุกครั้งที่กดสร้างใบเสร็จ ระบบจะอัปโหลดไฟล์เข้าโฟลเดอร์ Drive ให้เอง ตั้งค่าไอดีโฟลเดอร์ไว้ในชีต **ตั้งค่า** หัวข้อ *โฟลเดอร์ Drive เก็บใบเสร็จ* (เว้นว่างถ้าไม่อยากให้อัปโหลด)

ค่าเริ่มต้นเก็บ **ทั้ง PDF และ HTML** เปลี่ยนได้ที่หัวข้อ *รูปแบบไฟล์ที่เก็บใน Drive* ใส่ `PDF` `HTML` หรือ `ทั้งคู่`

> **ทำไมเก็บ HTML ด้วย** — PDF ที่แปลงฝั่ง Google บางครั้งฟอนต์ไทยไม่สวยเท่าการสั่งพิมพ์จากเบราว์เซอร์ ไฟล์ HTML เปิดแล้วกดพิมพ์ได้เหมือนกันทุกประการ เก็บไว้เป็นตัวสำรอง ถ้าเปิด PDF แล้วสระวรรณยุกต์เพี้ยน ให้ใช้ HTML แทน

ถ้าออกใบเสร็จเลขเดิมซ้ำ ไฟล์เก่าชื่อเดียวกันจะถูกย้ายลงถังขยะก่อน จะได้ไม่มีไฟล์ซ้อนกันหลายอัน

**ครั้งแรกต้องอนุญาตสิทธิ์ Drive เพิ่ม** ดูหัวข้อ *อัปเดตจากเวอร์ชันก่อน* ด้านล่าง

### แก้ไขใบเสร็จ

เข้า บันทึก → ดูรายการที่บันทึกไว้ → *5 ขาย* บิลที่ออกใบเสร็จแล้วจะมีเลขที่ใบเสร็จกำกับใต้รายการ และมีปุ่มเพิ่ม

- **📄** เปิดไฟล์ที่เก็บใน Drive
- **🧾** แก้ไขใบเสร็จ ระบบดึงค่าเดิมมาให้ทั้งหมด แก้แล้วกดบันทึก จะใช้เลขเดิมและแทนที่ไฟล์เดิมใน Drive

### ดูใบเสร็จที่ออกไปแล้วทั้งหมด

หน้ารายการที่บันทึก มีปุ่ม **ดูใบเสร็จที่ออกแล้วทั้งหมด** หรือกด *ใบเสร็จทั้งหมด* ที่มุมขวาบนของหน้าออกใบเสร็จ ค้นหาด้วยเลขที่หรือชื่อลูกค้าได้

### ผู้รับเงิน

พิมพ์ชื่อเองได้ พอกดสร้างใบเสร็จ ระบบจะจำไว้ในชีต **ผู้รับเงิน** ครั้งต่อไปเลือกจากดรอปดาวน์ได้เลย ชื่อนี้จะขึ้นในวงเล็บใต้เส้นลายเซ็นฝั่งผู้รับเงิน

### ชื่อสินค้าในใบเสร็จ

ดึงจากชีต **สินค้า** โดยตรง ช่อง *ชื่อสินค้า* จะเป็นชื่อแบรนด์ เช่น Wednesday · ตาหนวด ส่วนช่อง *รายละเอียด* ประกอบขึ้นเอง เช่น `เมล็ดกาแฟอาราบิก้า คั่วระดับกลาง 500g` ถ้าเปลี่ยนชื่อสินค้าในชีต ใบเสร็จที่ออกใหม่จะเปลี่ยนตาม

### ลูกค้า

ครั้งแรกให้พิมพ์เอง พอกดสร้างใบเสร็จ ระบบจะบันทึกลงชีต **ลูกค้า** ให้อัตโนมัติ ครั้งต่อไปเลือกจากดรอปดาวน์ *เลือกลูกค้าที่เคยบันทึก* แล้วช่องทั้งหมดจะเติมให้เอง ถ้าข้อมูลลูกค้าเปลี่ยน แก้ในช่องแล้วกดสร้างใบเสร็จ ระบบจะอัปเดตให้

### รายละเอียดที่ควรรู้

**เลขที่ใบเสร็จ** ระบบรันต่อให้อัตโนมัติภายในปีนั้น เช่น RMER2026006 แต่แก้ทับได้ทุกเมื่อ ถ้าออกใบเสร็จซ้ำของบิลเดิม จะใช้เลขเดิมและทับข้อมูลเก่า ไม่กินเลขใหม่

**ค่าจัดส่ง** ถ้าบิลนั้นเก็บค่าส่งจากลูกค้า จะขึ้นเป็นอีกบรรทัดในตารางสินค้าอัตโนมัติ

**หักมัดจำ** ใส่จำนวนเงินกับเลขที่ใบมัดจำได้ ยอดรวมทั้งสิ้นจะหักให้เอง

**QR พร้อมเพย์** สร้างในเครื่องเลย ไม่ได้ส่งข้อมูลไปเว็บอื่น และมียอดเงินฝังอยู่ในโค้ด ลูกค้าสแกนแล้วขึ้นจำนวนให้พร้อมโอน ติ๊กออกได้ถ้าไม่อยากให้แสดง

**ต้นฉบับ + สำเนา** เลือกได้ว่าจะพิมพ์แบบไหน ค่าเริ่มต้นคือ 2 แผ่น ต้นฉบับกับสำเนา แยกหน้ากันตอนพิมพ์

**ตัวอักษรจำนวนเงิน** แปลงให้อัตโนมัติ รองรับหลักล้าน คำว่าเอ็ด ยี่สิบ และสตางค์

**ทุกใบที่ออกจะถูกบันทึกในชีต ใบเสร็จ** ตรวจย้อนหลังได้ว่าออกให้ใคร เมื่อไหร่ เลขที่อะไร

### ถ้ากดสร้างใบเสร็จแล้วไม่มีอะไรขึ้น

เบราว์เซอร์บล็อกการเปิดหน้าต่างใหม่ ให้อนุญาต popup ของเว็บนี้ แล้วลองใหม่

## แดชบอร์ดในหน้าสรุป

หน้าสรุปมีแผนภูมิ 6 อัน เปลี่ยนตามช่วงเวลาที่เลือก (รายวัน / รายเดือน / รายปี)

**1. ต้นทุน 100 บาทไปไหนบ้าง** — แท่งเดียวแบ่งสัดส่วน เมล็ด · ซอง+สติ๊กเกอร์ · กล่อง+บับเบิ้ล+เทป · ค่าส่งส่วนที่ขาดทุน · กำไร
ดูอันนี้ก่อนเสมอ ถ้าช่องวัสดุหรือค่าส่งบวมขึ้นเรื่อย ๆ แปลว่ากำไรกำลังรั่วตรงนั้น

**2. แนวโน้มรายได้กับกำไร** — แท่งคือรายได้ เส้นคือกำไรสุทธิ
ถ้ารายได้ขึ้นแต่เส้นกำไรแบนหรือลง แปลว่าขายเยอะขึ้นแต่ไม่ได้กำไรเพิ่ม ต้องไปดูราคาขายหรือต้นทุน

**3. ยอดขายแยกระดับคั่ว × ขนาด** — 8 อันดับแรก ใช้วางแผนว่ารอบหน้าควรคั่วระดับไหนเยอะ ขนาดไหนขายดี

**4. Yield แต่ละรอบผลิต** — เส้นเขียวคือสี เส้นส้มคือคั่ว เส้นประคือค่ามาตรฐาน
จุดที่กลายเป็นสีแดงคือรอบที่ต่างจากมาตรฐานเกิน 5 จุด ถ้าเห็นแดงติดกันหลายรอบ ควรไปคุยกับโรงสีหรือคนคั่ว
นี่คือกราฟที่คุ้มค่าที่สุดในหน้านี้ เพราะ yield ตก 3-4% กินกำไรมากกว่าการลดราคาขายเสียอีก

**5. กำไรตามช่องทาง** — เทียบ นัดรับ / ส่งพัสดุ / ฝากส่ง แถบบนคือรายได้ แถบล่างคือกำไร
ถ้าช่องทางไหนแถบล่างสั้นกว่าที่ควร แปลว่าค่าส่งหรือค่าแพ็คกินกำไรไปมาก

**6. มูลค่าสต๊อกแยกประเภท** — โดนัทบอกว่าเงินจมอยู่ขั้นไหน กะลา สารเขียว เมล็ดคั่ว หรือวัสดุ
ถ้าเมล็ดคั่วจมเยอะควรเร่งระบาย เพราะมีวันหมดอายุ ต่างจากกะลาที่เก็บได้นานกว่า

**หมายเหตุ** กราฟทั้งหมดวาดด้วย SVG ในตัวแอปเอง ไม่ได้ดึงไลบรารีจากอินเทอร์เน็ต จึงใช้งานได้แม้ไม่มีสัญญาณ แลกกับหน้าตาที่เรียบกว่ากราฟสำเร็จรูป

## เมื่อระบบเริ่มช้า

Apps Script เสียเวลาไปกับการ "คุยกับ Google Sheets" มากกว่าการคำนวณหลายเท่า ยิ่งเรียกอ่าน-เขียนชีตบ่อย ยิ่งช้า เวอร์ชันนี้ลดจำนวนครั้งที่ต้องคุยกับชีตลงไปมาก

| การกระทำ | เดิม | ปัจจุบัน |
|---|---|---|
| บันทึกการขาย 1 บิล | 47 ครั้ง | 8 ครั้ง |
| โหลดหน้าหลัก | 16 ครั้ง | 9 ครั้ง |
| เปิดหน้าสรุป | 49 ครั้ง | 9 ครั้ง |
| **รวมต่อการบันทึก 1 ครั้ง** | **63 ครั้ง** | **17 ครั้ง** |

ที่แก้ไปคือ อ่านชีตแต่ละแผ่นแค่ครั้งเดียวต่อ 1 คำขอแล้วเก็บไว้ในหน่วยความจำ · เขียนยอดคงเหลือทั้งหมดครั้งเดียวตอนจบแทนการเขียนทีละรายการ · และเลิกตรวจโครงสร้างชีตทุกครั้งที่บันทึก (ย้ายไปทำตอนรัน `setupSheets` เท่านั้น)

หลังบันทึกเสร็จ ข้อความยืนยันจะบอกเวลาที่ใช้จริงด้วย เช่น *บันทึกการขายแล้ว · 1.2 วิ* จะได้รู้ว่าช้าลงเมื่อไหร่

### ดูแลรายเดือน

ชีต **ล็อตสินค้า** ถูกอ่านทั้งแผ่นทุกครั้งที่ตัดสต๊อก ยิ่งแถวเยอะยิ่งช้าลงเรื่อย ๆ เดือนละครั้งให้รันฟังก์ชัน **`archiveEmptyLots`** ใน Apps Script ระบบจะย้ายล็อตที่ใช้หมดแล้ว (คงเหลือ 0 และเก่ากว่า 30 วัน) ไปเก็บที่ชีต *ล็อตสินค้า (ประวัติ)* ตัวเลขทุกอย่างไม่เปลี่ยน เพราะล็อตที่หมดแล้วไม่ถูกใช้คำนวณอยู่แล้ว

เก็บล็อตอายุไม่เกิน 30 วันไว้เสมอ เผื่อต้องย้อนกลับไปลบหรือแก้ไขรายการเก่า

### ถ้าแก้โค้ดแล้วแอปพัง

ข้อดีของการเก็บโค้ดบน GitHub คือย้อนกลับได้ทุกเวอร์ชัน

1. เข้า repo → แท็บ **Commits** (อยู่เหนือรายการไฟล์)
2. หาเวอร์ชันก่อนหน้าที่ยังใช้งานได้ กดเข้าไป
3. กดปุ่ม **⋯** มุมขวา → **Revert**

Cloudflare จะสร้างเวอร์ชันใหม่จากโค้ดเดิมให้เองใน 1-2 นาที

อีกวิธีคือเข้า Cloudflare Pages → แท็บ **Deployments** → หาเวอร์ชันที่ใช้ได้ → **Rollback to this deployment** วิธีนี้เร็วกว่าแต่แก้แค่ที่เว็บ โค้ดใน GitHub ยังเป็นตัวที่พังอยู่

### ย้ายจาก Netlify มา Cloudflare Pages

ถ้าใช้ Netlify อยู่แล้วและอยากย้าย ทำตามลำดับนี้ **อย่าข้ามข้อ 1**

1. **เคลียร์รายการค้างก่อน** — เปิดแอปตัวเดิมบน Netlify ต่อเน็ตให้เรียบร้อย เข้าหน้าตั้งค่า ถ้าเห็นข้อความเตือนว่ามีรายการที่ยังไม่ได้ส่ง ให้กด *ดึงข้อมูลใหม่* จนคำเตือนหายไป
   รายการที่บันทึกตอนออฟไลน์เก็บอยู่ในเครื่องแยกตามโดเมน ถ้าย้ายก่อนส่งจะหายไปเลย
2. **คัดลอก URL ของ Apps Script** — ในหน้าตั้งค่ามีปุ่ม *คัดลอก URL สำหรับย้ายไปโดเมนใหม่*
3. **อัปโหลดขึ้น Cloudflare Pages** ตามขั้นที่ 2 ด้านบน
4. **ติดตั้งแอปใหม่จากลิงก์ใหม่** ลงหน้าจอโฮม แล้ววาง URL ที่คัดลอกไว้ในหน้าตั้งค่า
5. **ลบแอปตัวเก่าออกจากหน้าจอโฮม** เพื่อไม่ให้เผลอเปิดผิดตัว
6. เก็บโปรเจกต์ Netlify ไว้เฉย ๆ ได้ ไม่เสียค่าใช้จ่าย ใช้เป็นตัวสำรองเวลา Cloudflare มีปัญหา

**ข้อมูลทั้งหมดอยู่ใน Google Sheets ไม่ได้อยู่ที่ Netlify หรือ Cloudflare** การย้ายจึงไม่กระทบสต๊อก ต้นทุน หรือประวัติใด ๆ เปลี่ยนแค่ที่วางไฟล์หน้าเว็บเท่านั้น

**สิ่งที่จะดีขึ้นและไม่ดีขึ้น** — ดีขึ้นคือแอปเปิดไวขึ้นเล็กน้อยเพราะ Cloudflare มีเซิร์ฟเวอร์ใกล้ไทยกว่า และไม่มีเพดานปริมาณการใช้งาน ส่วนที่ *ไม่* เปลี่ยนคือความเร็วตอนบันทึกและอาการ failed to fetch เพราะสองอย่างนั้นขึ้นกับ Google Apps Script กับสัญญาณเน็ต ไม่เกี่ยวกับที่วางไฟล์

### อัปเดตจากเวอร์ชันก่อน — ต้องทำ 2 อย่าง

**1. รัน `setupSheets` เพื่อเติมหัวข้อตั้งค่าใหม่**

หัวข้อในชีต **ตั้งค่า** จะถูกเขียนตอนสร้างชีตครั้งแรกเท่านั้น ถ้าชีตมีอยู่แล้ว หัวข้อที่เพิ่มมาทีหลัง เช่น *URL โลโก้* หรือ *ที่อยู่กิจการ* จะไม่โผล่มาเอง จึงเป็นสาเหตุที่โลโก้และที่อยู่ไม่ขึ้นบนใบเสร็จ

เวอร์ชันนี้แก้แล้ว — รันฟังก์ชัน **`setupSheets`** หนึ่งครั้ง ระบบจะเติมหัวข้อที่ยังไม่มีต่อท้ายชีตให้ **ค่าที่กรอกไว้แล้วไม่ถูกแตะ** และจะบอกด้วยว่าเพิ่มอะไรไปบ้าง

จากนั้นเปิดชีตตั้งค่า เลื่อนลงล่างสุด กรอก *ชื่อบัญชี* กับ *เลขที่บัญชี* ให้ครบ

**2. อนุญาตสิทธิ์ Google Drive**

การอัปโหลดไฟล์ต้องใช้สิทธิ์ใหม่ที่ยังไม่เคยขอ ให้รัน `setupSheets` จากหน้า Apps Script ก่อน ระบบจะขึ้นหน้าขออนุญาต กด *ตรวจสอบสิทธิ์ → เลือกบัญชี → ขั้นสูง → ไปที่... → อนุญาต*

ถ้าไม่ทำขั้นนี้ เวลากดสร้างใบเสร็จจะขึ้นว่าอัปขึ้น Drive ไม่สำเร็จ แต่ตัวใบเสร็จยังเปิดและพิมพ์ได้ตามปกติ

**อย่าลืม deploy ใหม่หลังวางโค้ด**

### อัปโหลดแล้วขึ้นว่า "ไม่ได้รับอนุญาตให้เรียกใช้ DriveApp"

แปลว่าสคริปต์ยังไม่ได้รับสิทธิ์เข้าถึง Google Drive ไม่เกี่ยวกับไอดีโฟลเดอร์

เกิดขึ้นเพราะตอนกดอนุญาตครั้งแรก โค้ดยังไม่มีส่วนที่ใช้ Drive สิทธิ์ที่ได้จึงมีแค่ Sheets การรัน `setupSheets` ก็ไม่ได้ขอเพิ่ม เพราะฟังก์ชันนั้นไม่ได้แตะ Drive

**วิธีแก้ — รัน `authorizeDrive` หนึ่งครั้ง**

1. เปิด Apps Script → เลือกฟังก์ชัน **`authorizeDrive`** → กด **เรียกใช้**
2. หน้าต่างขออนุญาตจะเด้งขึ้น กด *ตรวจสอบสิทธิ์ → เลือกบัญชี → ขั้นสูง → ไปที่... → อนุญาต*
   คราวนี้จะเห็นรายการขอสิทธิ์ **"ดู แก้ไข สร้าง และลบไฟล์ Google ไดรฟ์ทั้งหมดของคุณ"** เพิ่มมา ต้องมีบรรทัดนี้
3. ดูผลใน **บันทึกการดำเนินการ** ควรขึ้น ✓ ทั้งสองโฟลเดอร์
4. **Deploy ใหม่** แล้วลองอัปโหลดจากแอป

ฟังก์ชันนี้ทดสอบถึงขั้นสร้างไฟล์จริงแล้วลบทิ้ง จึงยืนยันได้ว่าเขียนไฟล์ลงโฟลเดอร์ได้จริง ไม่ใช่แค่เปิดดูได้

**ถ้าขึ้น ✗** ให้ดูบัญชีที่แสดงในบรรทัดแรกของผลลัพธ์ ว่าเป็นบัญชีเดียวกับเจ้าของโฟลเดอร์ไหม ถ้าคนละบัญชี ต้องแชร์โฟลเดอร์ให้บัญชีนั้นเป็น **ผู้แก้ไข** ก่อน

**ทางเลือกสำรอง ถ้าหน้าต่างขออนุญาตไม่เด้ง**

ใส่ไฟล์ `appsscript.json` ที่ให้มาด้วย เพื่อประกาศสิทธิ์ให้ชัดเจน

1. ใน Apps Script กด **การตั้งค่าโปรเจ็กต์** (รูปเฟือง)
2. ติ๊ก **แสดงไฟล์ appsscript.json**
3. กลับไปแท็บ **ตัวแก้ไข** จะเห็นไฟล์ `appsscript.json` เพิ่มมา
4. วางเนื้อหาจากไฟล์ที่ให้ทับลงไป แล้วบันทึก
5. รัน `authorizeDrive` อีกครั้ง

### ไอดีโฟลเดอร์ Drive

โฟลเดอร์ทั้งสอง **มีค่าตั้งต้นอยู่ในโค้ดแล้ว** ต่อให้ในชีตตั้งค่าไม่มีแถวนั้นหรือค่าว่าง ระบบก็ยังอัปโหลดเข้าโฟลเดอร์เดิมได้ ถ้าอยากเปลี่ยนโฟลเดอร์ค่อยกรอกในชีต ค่าในชีตจะถูกใช้ก่อนเสมอ

ช่องนี้ใส่ได้ทั้ง **ไอดี** และ **ลิงก์เต็ม** ระบบตัดเอาเฉพาะไอดีให้เอง และทนต่อการพิมพ์ชื่อหัวข้อเว้นวรรคไม่ตรงด้วย

**ถ้าอัปโหลดแล้วขึ้นว่าเปิดโฟลเดอร์ไม่ได้** ข้อความจะบอกไอดีที่ระบบใช้จริงมาด้วย ให้ตรวจว่า

- ไอดีตรงกับโฟลเดอร์ที่ต้องการไหม
- **บัญชี Google ที่ใช้ deploy สคริปต์** มีสิทธิ์เข้าโฟลเดอร์นั้นไหม (ถ้าโฟลเดอร์เป็นของอีกบัญชี ต้องแชร์ให้บัญชีนี้แก้ไขได้ก่อน)

### ซ่อมทุกอย่างในคำสั่งเดียว: fixEverything

ถ้าเจอปัญหาหลายอย่างพร้อมกัน — ข้อมูลอยู่ผิดช่อง ลิงก์หาย error รหัสสินค้า — ให้รันฟังก์ชัน **`fixEverything`** ครั้งเดียว จะทำให้ตามลำดับ

1. **`alignColumns`** จัดเรียงคอลัมน์ทุกชีตให้ตรงกับที่โค้ดต้องการ **โดยย้ายข้อมูลไปพร้อมหัวคอลัมน์** ไม่ใช่แค่เปลี่ยนชื่อ
2. **`repairShiftedData`** ย้ายลิงก์หลักฐาน/ใบเสร็จที่หลงช่องกลับที่เดิม และลบแถวสินค้ารหัสเสีย

**ก่อนรัน แนะนำให้ดูสภาพก่อนด้วย `showHeaders`** จะบอกว่าชีตไหนคอลัมน์ตรงแล้ว ชีตไหนเพี้ยน ขาดคอลัมน์อะไร มีคอลัมน์แปลกอะไรเกินมา

> **อย่าแก้ชื่อหัวคอลัมน์เองด้วยมือ** เพราะข้อมูลข้างล่างจะไม่ขยับตาม กลายเป็นข้อมูลติดป้ายผิด ให้ใช้ `alignColumns` แทน มันย้ายข้อมูลให้ด้วย

**คอลัมน์ที่คุณเพิ่มเองจะไม่หาย** ระบบเก็บไว้ต่อท้ายชีตเสมอ

**สำรองไฟล์ก่อนรันจะอุ่นใจกว่า** — ในสเปรดชีตกด ไฟล์ → สร้างสำเนา เก็บไว้สักชุด

### หลักฐาน/ใบเสร็จที่เคยแนบไว้หายไป (ทั้งที่ไฟล์ยังอยู่ใน Drive)

เกิดจากเวอร์ชันก่อนหน้าที่เขียนค่าลงชีตโดยนับตำแหน่งคอลัมน์ ทำให้ลิงก์หลักฐานไปตกอยู่ในช่อง **หมายเหตุ** และไอดีไฟล์ไปอยู่ในช่อง **ผู้บันทึก** พอระบบเปลี่ยนมาอ่านตามชื่อคอลัมน์ที่ถูกต้อง ช่องจริงจึงว่างเปล่า

**ไฟล์ใน Drive ไม่ได้หายไปไหน** แค่ระบบหาลิงก์ไม่เจอ

**วิธีแก้ รันครั้งเดียว**

1. Apps Script → เลือกฟังก์ชัน **`repairShiftedData`** → **เรียกใช้**
2. ดูผลใน **บันทึกการดำเนินการ** จะบอกว่ากู้อะไรคืนมาบ้าง
3. กลับไปที่แอป หน้าตั้งค่า → **ล้างข้อมูลที่จำไว้ในเครื่อง แล้วดึงใหม่**

ฟังก์ชันนี้ทำ 3 อย่าง — ย้ายลิงก์หลักฐานกับไอดีไฟล์กลับเข้าช่องที่ถูกต้อง · ย้ายลิงก์ไฟล์ใบเสร็จกลับที่เดิม · ลบแถวสินค้าที่รหัสเสียซึ่งเป็นต้นเหตุของ error "ไม่พบสินค้ารหัส"

รันซ้ำได้ไม่เสียหาย ถ้าข้อมูลอยู่ถูกที่แล้วจะข้ามไปเอง

### รายการสินค้าในแอปไม่ตรงกับในชีต

แอปเก็บสำเนารายการสินค้าไว้ในเครื่องเพื่อให้ใช้ออฟไลน์ได้ ถ้าไปลบหรือแก้สินค้าในชีต สำเนาในเครื่องจะยังเป็นของเก่า พอเลือกสินค้าตัวนั้นแล้วกดบันทึก เซิร์ฟเวอร์จะบอกว่าไม่พบรหัสสินค้า

**วิธีแก้** หน้าตั้งค่า → ปุ่ม **ล้างข้อมูลที่จำไว้ในเครื่อง แล้วดึงใหม่**

ตอนนี้แอปตรวจให้อัตโนมัติด้วย ถ้าจะบันทึกการขายแล้วพบว่ารหัสสินค้าใช้ไม่ได้ ระบบจะดึงข้อมูลใหม่ให้เองแล้วบอกว่าให้กดบันทึกอีกครั้ง ถ้าสินค้านั้นถูกลบไปจริง ๆ จะบอกชื่อให้ลบออกจากรายการก่อน

> ถ้ามีรายการค้างที่ยังไม่ได้ส่งขึ้นชีต ปุ่มล้างจะถามยืนยันก่อน เพราะรายการเหล่านั้นจะหายไปด้วย

### เซิร์ฟเวอร์ตอบ 404

มักเกิดจาก URL ของ Apps Script ในหน้าตั้งค่าไม่ใช่ตัวล่าสุด ให้ตรวจว่า

- ลงท้ายด้วย `/exec` ไม่ใช่ `/dev`
- เป็น deployment ที่ยังใช้งานอยู่ (ถ้าเคยลบ deployment เก่าทิ้ง URL เดิมจะใช้ไม่ได้)

ระบบจะลองใหม่ให้อัตโนมัติ 3 ครั้งก่อนแจ้งเตือน เพราะบางครั้งเป็นอาการขัดข้องชั่วคราวของ Google

### สแกนหาเซลล์เสียด้วย findBadCells

ถ้าขึ้น error ที่มีคำว่า *เวลาอินโดจีน* หรือ *GMT* แปลว่ามีเซลล์ในชีตเก็บเศษข้อความวันที่ไว้ผิดที่

1. เปิด Apps Script → เลือกฟังก์ชัน **`findBadCells`** → **เรียกใช้**
2. ดูผลใน **บันทึกการดำเนินการ** จะบอกชื่อชีต แถว คอลัมน์ และค่าที่มีปัญหา
3. เข้าไปแก้หรือลบเซลล์นั้นในชีตโดยตรง

**ถ้าปัญหาอยู่ในชีตสินค้า** รันฟังก์ชัน **`removeBadProducts`** ระบบจะลบเฉพาะแถวที่รหัสสินค้าผิดปกติหรือว่างเปล่าให้ พร้อมบอกว่าลบอะไรไปบ้าง แถวสินค้าปกติไม่ถูกแตะ

**การขายจะไม่ล้มทั้งบิลอีกแล้ว** ถ้าเจอรหัสวัสดุที่ใช้ไม่ได้ ระบบจะข้ามเฉพาะตัวนั้น บันทึกบิลต่อให้ปกติ แล้วขึ้นคำเตือนบอกว่าข้ามอะไรไป จะได้ไม่ติดขัดตอนขายจริง

### หาสาเหตุด้วย diagnoseSale

ถ้าแก้ไขบิลขายแล้วยังขึ้น error แปลก ๆ ให้รันฟังก์ชัน **`diagnoseSale`** ใน Apps Script แล้วดูผลใน **บันทึกการดำเนินการ**

- ใส่เลขที่บิลก็ได้ เช่น เปลี่ยนบรรทัดในฟังก์ชันเป็น `diagnoseSale('SO2608-012')`
- ไม่ใส่ = ตรวจบิลล่าสุดให้เอง

รายงานจะบอก
- **เวอร์ชันโค้ดที่กำลังรันจริง** (ถ้าไม่ตรงกับที่เพิ่งวาง แปลว่ายังไม่ได้ deploy)
- ลำดับหัวคอลัมน์จริงของชีตขายและชีตรายการขาย
- ค่าทุกช่องพร้อมชนิดข้อมูล ช่องไหนเป็นวันที่ทั้งที่ไม่ควรเป็น จะมีสัญลักษณ์ ⚠
- รหัสสินค้าที่ระบบจับคู่ได้จากแต่ละบรรทัด และพบในชีตสินค้าหรือไม่

ข้อความ error ทุกอันตอนนี้จะต่อท้ายด้วยเวอร์ชันเซิร์ฟเวอร์ เช่น `[เซิร์ฟเวอร์ 2026.08.27-ตรวจบิล]` ใช้ยืนยันได้ทันทีว่าโค้ดที่รันอยู่เป็นตัวไหน

### ขึ้นข้อความแปลก ๆ ที่มีคำว่า "เวลาอินโดจีน"

เกิดจากค่าวันที่ไปโผล่ในช่องที่ควรเป็นข้อความอื่น ต้นเหตุคือ **ลำดับคอลัมน์ในชีตไม่ตรงกับที่โค้ดคาดไว้**

เวลาเพิ่มฟีเจอร์ใหม่ที่ต้องใช้คอลัมน์เพิ่ม ระบบจะเติมคอลัมน์นั้นไว้ **ท้ายสุด** ของชีตเสมอ แต่ถ้าในโค้ดกำหนดให้อยู่ตรงกลาง การอ่านค่าแบบนับตำแหน่งจะเลื่อนกันทั้งแถว ช่อง *หมายเหตุ* จึงไปอ่านค่าจากช่อง *บันทึกเมื่อ* ซึ่งเป็นวันที่

เวอร์ชันนี้แก้แล้ว — ระบบอ่านและเขียนโดย **จับคู่จากชื่อหัวคอลัมน์จริง** ไม่ใช่ตำแหน่ง ลำดับคอลัมน์ในชีตจะสลับอย่างไรก็ได้ ไม่กระทบอีกต่อไป และไม่ต้องไปจัดเรียงคอลัมน์เองด้วย

> **อย่าแก้ชื่อหัวคอลัมน์ในแถวแรกของชีต** เพราะเป็นตัวที่ระบบใช้จับคู่ ถ้าเผลอแก้ ให้พิมพ์กลับเป็นชื่อเดิมแล้วรัน `setupSheets`

### ตรวจว่าตั้งค่าครบไหม

รันฟังก์ชัน **`checkSettings`** ใน Apps Script แล้วดูผลใน **บันทึกการดำเนินการ** จะบอกว่า

- ชื่อสเปรดชีตกับชื่อชีตตั้งค่าที่สคริปต์มองเห็น (ถ้าผิดไฟล์จะรู้ทันที)
- หัวข้อไหนมีแล้ว หัวข้อไหนขาด และค่าที่กรอกไว้คืออะไร
- เวอร์ชันโค้ดที่อยู่ในไฟล์นั้นจริง ๆ

`✗` = ไม่มีแถวนั้น ให้รัน `setupSheets` · `△` = มีแถวแต่ยังไม่ได้กรอกค่า

**ทางลัด** ถ้าไม่อยากพิมพ์ไอดีโฟลเดอร์เอง รันฟังก์ชัน **`setDriveFolders`** ระบบจะใส่ไอดีทั้งสองโฟลเดอร์ให้เลย

### หัวข้อตั้งค่าใหม่ไปโผล่ไกลจนหาไม่เจอ

ถ้าในชีตตั้งค่ามีข้อความหลงอยู่แถวล่าง ๆ เช่นเผลอพิมพ์โน้ตไว้ที่แถว 200 เวอร์ชันก่อนจะเติมหัวข้อใหม่ต่อจากแถวนั้น ทำให้เหมือนหัวข้อหายไป

เวอร์ชันนี้แก้แล้ว หัวข้อใหม่จะต่อท้ายหัวข้อสุดท้ายจริง ๆ เสมอ ถ้าเคยเจอปัญหานี้ ให้เลื่อนลงไปดูแถวล่าง ๆ ว่ามีหัวข้อซ้ำค้างอยู่ไหม ถ้ามีให้ลบทิ้งแล้วรัน `setupSheets` ใหม่

### แก้ Code.gs แล้วฟีเจอร์ใหม่ไม่ทำงาน

**การวางโค้ดใน Apps Script แล้วกดบันทึกยังไม่พอ** เว็บแอปจะเสิร์ฟเฉพาะเวอร์ชันที่ deploy ไว้เท่านั้น ต้อง deploy ใหม่ทุกครั้งที่แก้ `Code.gs`

1. **ทำให้ใช้งานได้** → **จัดการการทำให้ใช้งานได้**
2. กดรูป **ดินสอ ✏️** ที่ deployment เดิม
3. ช่อง **เวอร์ชัน** เปลี่ยนเป็น **ใหม่**
4. กด **ทำให้ใช้งานได้**

> แก้ deployment เดิมเท่านั้น **อย่าสร้างใหม่** ไม่งั้น URL จะเปลี่ยนแล้วต้องไปตั้งค่าในแอปใหม่

**อาการที่บอกว่าลืม deploy** — ของเก่ายังทำงานปกติ แต่ฟีเจอร์ที่เพิ่งเพิ่มไม่ขึ้น เช่น กราฟบางอันว่างทั้งที่มีข้อมูล

**วิธีเช็คให้ชัด** เปิดหน้า **ตั้งค่า** ในแอป ล่างสุดจะบอกเวอร์ชันของทั้งสองฝั่ง

```
แอป 2026.08.15-แดชบอร์ด · เซิร์ฟเวอร์ 2026.08.15-แดชบอร์ด
```

ถ้าเลขสองฝั่งไม่ตรงกัน จะมีคำเตือนสีเหลืองขึ้นพร้อมบอกวิธีแก้

### แก้โค้ดแล้วแอปยังเป็นของเดิม

สาเหตุที่พบบ่อยที่สุดคือ **มือถือยังใช้ไฟล์ที่เก็บไว้ในเครื่อง** ไม่ใช่ Cloudflare ไม่อัปเดต แอปแบบติดตั้งลงหน้าจอโฮมจะเก็บไฟล์ไว้ใช้ตอนออฟไลน์ ถ้าไม่บอกให้มันโหลดใหม่ ก็จะใช้ของเดิมต่อไป

**ตรวจว่าฝั่งไหนมีปัญหา** — เปิดลิงก์เว็บใน Chrome หรือ Safari (ไม่ใช่ไอคอนแอปบนหน้าจอโฮม) แล้วดูหน้าตั้งค่า จะมีเลขเวอร์ชันบอกอยู่ล่างสุด

- **เห็นของใหม่ในเบราว์เซอร์ แต่แอปยังเก่า** → เป็นที่แคชในเครื่อง แก้ตามด้านล่าง
- **เบราว์เซอร์ก็ยังเก่า** → เป็นที่ Cloudflare ยังไม่ได้ deploy ไปดูแท็บ **Deployments** ว่ารอบล่าสุดสำเร็จหรือยัง

**วิธีแก้ที่แคชในเครื่อง** เรียงจากง่ายไปยาก

1. เปิดแอป → หน้า **ตั้งค่า** → กดปุ่ม **บังคับโหลดแอปเวอร์ชันล่าสุด** วิธีนี้ควรได้ผลทันที
2. ปิดแอปจากรายการแอปที่เปิดอยู่ แล้วเปิดใหม่
3. ถ้ายังไม่ได้ ลบไอคอนแอปออกจากหน้าจอโฮม แล้วเปิดลิงก์ในเบราว์เซอร์ติดตั้งใหม่

**ป้องกันไม่ให้เกิดอีก** — ทุกครั้งที่แก้ `index.html` ให้แก้ 2 จุดนี้ด้วย

- `sw.js` บรรทัดแรก เปลี่ยนเลข `mtt-v5` เป็น `mtt-v6`, `v7` ไล่ไปเรื่อย ๆ
- `index.html` บรรทัด `var APPVER=` เปลี่ยนวันที่ให้ตรงกับที่แก้

เวอร์ชันนี้ปรับให้ตัวแอปดึงไฟล์จากเน็ตก่อนเสมอแล้ว (เดิมใช้ของในเครื่องก่อน) ครั้งต่อ ๆ ไปจึงควรอัปเดตเองโดยไม่ต้องกดอะไร

### ข้อความ "failed to fetch" คืออะไร

เป็นข้อความของเบราว์เซอร์ ไม่ใช่ข้อผิดพลาดจากระบบ แปลว่า **คำขอถูกส่งออกไปแล้วแต่คำตอบไม่กลับมา** สาเหตุที่พบบ่อยเรียงตามความเป็นไปได้

1. **เน็ตมือถือสะดุดชั่วขณะ** — พบบ่อยที่สุด โดยเฉพาะตอนสลับระหว่างไวไฟกับเน็ตมือถือ หรืออยู่ในที่สัญญาณอ่อน เช่น โรงสีหรือที่คั่ว
2. **บันทึกพร้อมกันหลายเครื่อง** — ระบบล็อกไม่ให้เขียนชนกัน อีกเครื่องจึงต้องรอ ถ้ารอนานเกินเบราว์เซอร์จะตัดการเชื่อมต่อ
3. **Google Apps Script ขัดข้องชั่วคราว** — เกิดได้เป็นครั้งคราว มักหายเองภายในไม่กี่นาที
4. **หน้าจอค้างไว้นานมาก** แล้วเพิ่งกลับมากด — เซสชันหมดอายุ ปิดแล้วเปิดแอปใหม่

**เรื่องสำคัญที่สุด** — ข้อความนี้ *ไม่ได้แปลว่าบันทึกไม่สำเร็จ* หลายครั้งข้อมูลลงชีตเรียบร้อยแล้ว แค่คำตอบหายกลางทาง ถ้ากดบันทึกซ้ำทันทีจะกลายเป็นรายการซ้ำ

เวอร์ชันนี้แก้ให้แล้ว 3 ชั้น

- **ลองใหม่ให้อัตโนมัติ** สูงสุด 3 ครั้ง เว้นระยะห่างขึ้นเรื่อย ๆ ระหว่างนั้นจะขึ้นข้อความ *เน็ตสะดุด กำลังลองใหม่…* ส่วนใหญ่จะผ่านในรอบที่สองโดยไม่ต้องทำอะไร
- **กันบันทึกซ้ำ** ทุกคำขอมีรหัสประจำตัว ถ้าคำขอเดิมบันทึกสำเร็จไปแล้วแต่คำตอบหาย พอลองใหม่ระบบจะคืนผลเดิมกลับมาแทนการบันทึกซ้ำ รหัสนี้เก็บไว้ 6 ชั่วโมง
- **กำหนดเวลารอสูงสุด** 60 วินาที แทนที่จะค้างไม่มีกำหนด

**ถ้ายังขึ้นข้อความนี้อยู่** ให้เข้าไปดูที่ *รายการที่บันทึก* ก่อนเสมอ ถ้ารายการเข้าไปแล้วก็ไม่ต้องทำอะไร ถ้ายังไม่เข้าค่อยบันทึกใหม่ ข้อความที่ขึ้นตอนนี้จะเตือนเรื่องนี้ให้ด้วย

ถ้าเกิดบ่อยผิดปกติทั้งที่สัญญาณดี ให้ตรวจว่า URL ในหน้าตั้งค่าลงท้ายด้วย `/exec` (ไม่ใช่ `/dev`) และสิทธิ์การเข้าถึงตั้งเป็น **ทุกคน**

### ถ้ายังช้าอยู่

- **เน็ตมือถือ** ถ้าสัญญาณอ่อน แต่ละคำขอจะช้าเองโดยที่โค้ดไม่เกี่ยว ลองเทียบกับตอนต่อไวไฟ
- **ชีตมีสูตรหรือ Conditional formatting เยอะ** ทุกครั้งที่เขียนค่า Google จะคำนวณสูตรใหม่ทั้งไฟล์ ถ้าเคยใส่สูตรเพิ่มเองในชีต ลองเอาออกดู
- **ไฟล์ใหญ่เกิน** ถ้าใช้ไปหลายปีจนเกินหลักหมื่นแถว ให้แยกไฟล์ใหม่ต่อปี แล้วเก็บไฟล์เก่าไว้ดูย้อนหลัง
- **การแก้ไขรายการช้ากว่าการบันทึกใหม่** เป็นเรื่องปกติ เพราะต้องอ่านของเดิม ย้อนสต๊อก แล้วบันทึกใหม่ในคำขอเดียว

## หลักการคำนวณ

**ถัวเฉลี่ยถ่วงน้ำหนัก** ทุกครั้งที่ของเข้าคลัง
```
ต้นทุนเฉลี่ยใหม่ = (คงเหลือเดิม × ทุนเฉลี่ยเดิม + ต้นทุนรวมล็อตใหม่) ÷ คงเหลือรวม
```

**แต่ละขั้นผลิต**
```
ต้นทุนสารเขียว/kg = (ค่ากะลาที่ตัดเบิก + ค่าสี + ค่าส่ง) ÷ สารเขียวที่ได้จริง
ต้นทุนเมล็ดคั่ว/kg = (ค่าสารเขียวที่ใช้ + ค่าแรงคั่ว + ค่าเช่าเครื่อง) ÷ เมล็ดคั่วที่ได้จริง
ต้นทุน/ซอง        = ต้นทุนเมล็ดคั่ว/kg × น้ำหนักซอง + ซอง + สติ๊กเกอร์
```

**FEFO** — ของที่หมดอายุก่อนถูกตัดออกก่อน ทุกรายการบันทึกไว้ว่าตัดจากล็อตไหนบ้าง

## ข้อควรระวัง

- **อย่าลบแถวในชีตโดยตรง** ถ้าผิดให้บันทึกกลับทางหรือใช้ตรวจนับปรับยอด ประวัติจะได้ตรวจย้อนหลังได้
- **ชิมทดสอบและของแจก** บันทึกที่ บันทึก → ตัดจ่ายอื่นๆ ไม่ใช่ขายราคา 0
- **ตรวจนับเดือนละครั้ง** โดยเฉพาะสารเขียวกับเมล็ดคั่ว เพราะน้ำหนักเปลี่ยนได้จากความชื้น
- **ออฟไลน์** บันทึกได้ปกติ ระบบส่งขึ้นชีตอัตโนมัติเมื่อกลับมามีเน็ต
