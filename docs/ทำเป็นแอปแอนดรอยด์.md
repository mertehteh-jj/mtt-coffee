# ทำเป็นแอปแอนดรอยด์

มี 3 ทางเลือก เรียงจากง่ายไปยาก เลือกตามว่าจะใช้คนเดียวหรือแจกให้คนอื่น

| วิธี | ได้ไฟล์ APK | ลง Play Store | ความยาก | เหมาะกับ |
|---|---|---|---|---|
| 1. ติดตั้งจาก Chrome | ไม่ได้ | ไม่ได้ | ง่ายมาก | ใช้เอง 1-2 เครื่อง |
| 2. PWABuilder → APK | ได้ | ได้ | ปานกลาง | แจกให้พนักงาน / ลง Store |
| 3. เขียนแอปเนทีฟใหม่ | ได้ | ได้ | ยากมาก | ไม่แนะนำ |

---

## วิธีที่ 1 — ติดตั้งจาก Chrome (ที่ใช้อยู่ตอนนี้)

เปิดลิงก์ใน Chrome → เมนู ⋮ → **ติดตั้งแอป**

ได้ไอคอนบนหน้าจอโฮม เปิดแบบเต็มจอไม่มีแถบเบราว์เซอร์ ใช้ออฟไลน์ได้ อยู่ในรายการแอปเหมือนแอปทั่วไป

**ข้อจำกัด** — ส่งไฟล์ให้คนอื่นติดตั้งไม่ได้ ต้องส่งลิงก์แล้วให้เขากดติดตั้งเอง และลง Play Store ไม่ได้

ถ้าใช้คนเดียวหรือสองสามเครื่อง **วิธีนี้พอแล้ว** ไม่ต้องทำอะไรเพิ่ม

---

## วิธีที่ 2 — สร้างไฟล์ APK ด้วย PWABuilder

ได้ไฟล์ APK จริงที่ส่งให้คนอื่นติดตั้งได้ และเอาขึ้น Play Store ได้ ใช้เทคโนโลยีชื่อ TWA ซึ่งเป็นการห่อเว็บของเราให้เป็นแอป — โค้ดยังเป็นชุดเดิม แก้เว็บแล้วแอปอัปเดตตามเองโดยไม่ต้องส่ง APK ใหม่

### 2.1 อัปไฟล์ที่แก้แล้วขึ้น GitHub ก่อน

ต้องมี 3 ไฟล์นี้บนเว็บก่อนถึงจะสร้าง APK ได้

- `manifest.json` (ปรับใหม่ให้ผ่านเกณฑ์ของ PWABuilder แล้ว)
- `.well-known/assetlinks.json` (ไฟล์ยืนยันความเป็นเจ้าของโดเมน)
- `_headers` (กำหนดให้ assetlinks ส่งเป็น JSON)

> **ระวัง** โฟลเดอร์ `.well-known` ขึ้นต้นด้วยจุด บางครั้งลากอัปโหลดแล้วไม่ติดไปด้วย
> ตรวจโดยเปิด `https://ลิงก์ของคุณ/.well-known/assetlinks.json` ในเบราว์เซอร์ ต้องเห็นเนื้อหา JSON ไม่ใช่หน้า 404
> ถ้าไม่ขึ้น ให้สร้างไฟล์ใหม่บน GitHub โดยตรง — กด **Add file → Create new file** แล้วพิมพ์ชื่อเป็น `.well-known/assetlinks.json` GitHub จะสร้างโฟลเดอร์ให้เอง

### 2.2 สร้างแพ็กเกจ

1. เข้า https://www.pwabuilder.com
2. วางลิงก์แอป แล้วกด **Start**
3. รอตรวจคะแนน ถ้าผ่านจะมีปุ่ม **Package for stores**
4. เลือก **Android** → **Generate Package**
5. ตรวจค่าในหน้าตั้งค่า

   | ช่อง | ใส่อะไร |
   |---|---|
   | Package ID | `com.mertehteh.mttcoffee` |
   | App name | ต้นทุนกาแฟ เม่อะ เต เต |
   | Signing key | **Create new** (ครั้งแรก) |

6. ดาวน์โหลดไฟล์ zip จะได้ `.apk` (ไว้ทดสอบ) และ `.aab` (ไว้ขึ้น Play Store)

> **เก็บไฟล์ signing key ให้ดีที่สุด** อยู่ในซิปที่ดาวน์โหลดมา ถ้าหายแล้วจะอัปเดตแอปตัวเดิมไม่ได้อีกเลย ต้องทำแอปใหม่ทั้งตัว สำรองไว้อย่างน้อย 2 ที่

### 2.3 ใส่ fingerprint ลงใน assetlinks.json

ขั้นนี้**ห้ามข้าม** ไม่งั้นเปิดแอปแล้วจะมีแถบ URL ของเบราว์เซอร์โผล่อยู่ข้างบน

1. ในซิปที่ดาวน์โหลดมา เปิดไฟล์ `assetlinks.json` ที่ PWABuilder สร้างให้ คัดลอกค่า SHA-256 fingerprint
2. เข้า GitHub → เปิดไฟล์ `.well-known/assetlinks.json` → กดดินสอ ✏️
3. แทนที่ข้อความ `ใส่ค่า SHA-256 fingerprint ที่ได้จาก PWABuilder ตรงนี้` ด้วยค่าที่คัดลอกมา
4. ตรวจว่า `package_name` ตรงกับที่กรอกใน PWABuilder
5. Commit แล้วรอ Cloudflare อัปเดต 1-2 นาที

### 2.4 ติดตั้งทดสอบ

ส่งไฟล์ `.apk` เข้ามือถือ (LINE, อีเมล, สายUSB) แล้วกดเปิด ระบบจะถามอนุญาตติดตั้งจากแหล่งที่ไม่รู้จัก ให้กดอนุญาต

**เปิดแล้วมีแถบ URL โผล่?** แปลว่า assetlinks ยังไม่ถูกต้อง ตรวจตามนี้

- เปิด `https://ลิงก์ของคุณ/.well-known/assetlinks.json` เห็น JSON ไหม
- fingerprint ตรงกับที่ PWABuilder ให้มาไหม
- `package_name` ตรงกันทั้งสองที่ไหม
- ถ้าแก้แล้วยังเป็นเหมือนเดิม ให้ถอนแอปออก ล้างแคช Chrome แล้วติดตั้งใหม่ (Android จำค่าเดิมไว้)

### 2.5 ถ้าจะขึ้น Play Store

เสียค่าสมัครนักพัฒนาครั้งเดียว 25 ดอลลาร์ อัปโหลดไฟล์ `.aab` แล้วรอตรวจ

หลัง Google เซ็นแอปให้ **ต้องกลับมาเพิ่ม fingerprint ตัวใหม่** ใน assetlinks.json อีกค่าหนึ่ง หาได้จาก Play Console → **Setup → App integrity** ใส่เพิ่มเป็นสมาชิกตัวที่สองในลิสต์ คั่นด้วยจุลภาค อย่าลบตัวเดิมออก

> ถ้าแค่อยากให้พนักงานใช้ ไม่จำเป็นต้องขึ้น Play Store ส่งไฟล์ APK ให้ติดตั้งตรง ๆ ได้เลย

## วิธีที่ 3 — เขียนแอปเนทีฟใหม่

ต้องเขียนใหม่ทั้งระบบด้วย Kotlin หรือ Flutter **ไม่แนะนำ** เพราะได้ผลเท่าเดิมแต่ต้องดูแลโค้ดสองชุด และทุกครั้งที่แก้ต้องส่งเวอร์ชันใหม่ให้ผู้ใช้อัปเดตเอง ต่างจากวิธีที่ 2 ที่แก้เว็บแล้วแอปเปลี่ยนตามทันที

---

## สรุปว่าควรเลือกอะไร

- **ใช้เองคนเดียว** → วิธีที่ 1 พอ ไม่ต้องทำอะไรเพิ่ม
- **มีลูกน้องช่วยบันทึก 2-3 คน** → วิธีที่ 2 แต่ไม่ต้องขึ้น Play Store ส่ง APK ให้ติดตั้งเอง
- **อยากให้ดูเป็นทางการ ค้นหาเจอใน Play Store** → วิธีที่ 2 แบบเต็ม
